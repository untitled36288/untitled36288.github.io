# Jack Yang · 个人网站

网站地址：[www.jackyang.info](https://www.jackyang.info)

## 文件放在哪里？

| 目录 / 文件 | 用途 | 更新时怎么处理 |
| --- | --- | --- |
| `docs/` | 当前新版网站，GitHub Pages 的发布目录 | 从本地管理项目导出后更新这里 |
| `legacy/` | 之前未完成的旧版网页，完整保留原始文件 | 作为旧版存档，日常发布不需要修改 |
| `README.md` | 本说明 | 发布方式变化时更新 |

`legacy/` 只供仓库归档查看，不会作为当前网站发布，也没有设置在线旧版入口。旧版保留原路径写法，直接在子目录打开不保证链接和样式正常。

## 如何更新新版？

1. 在自己的电脑启动本地管理端，编辑作品、上传图片并保存。
2. 本地预览确认后，在完整管理项目中运行 `node prepare-publish.mjs`。
3. 将生成的 `github-pages-upload/docs` 同步到本仓库的 `docs/`，提交到 `main`。
4. 等待 GitHub Actions 的 Pages 部署成功，再检查网站。

GitHub Pages 设置：`Deploy from a branch` → `main` → `/docs`。自定义域名：`www.jackyang.info`。

网页上传只添加或覆盖文件，不会自动删除旧文件。若需要撤回旧图片，请同时删除 `docs/assets/` 中对应旧文件。

## 本地管理端与换电脑

这个公开仓库只保存公开网站和旧版存档。后台源码、未公开内容和本地备份保存在完整本地管理项目中；这里的 `docs/` 无法还原管理端。

换 Mac 时，应迁移完整本地项目，尤其是内容数据、作品图片和管理端源码。安装 Node.js 后，在项目目录运行 `node server.mjs` 即可启动本地管理端。

公开仓库不存放完整 CV 或论文全文。网页上的论文标题和会议信息保留。
